CATEGORY: OFFENSIVE & LINUX

Linux Concurrency, Race Condition Analysis & Kernel-Level Mitigation (flock)

Built multi-process Bash environments that reliably reproduce non-atomic read-modify-write race conditions, showing lost updates and data corruption under concurrent execution. Fixed it with POSIX exclusive file locking (flock -x) around the critical section, plus nice/renice scheduling and vmstat/top -H context-switch analysis.

ATTACK SURFACE / PROBLEM

A shared resource updated with a non-atomic read-modify-write sequence. When several processes interleave, they overwrite each other's results, so updates are lost and state is corrupted.

TECHNICAL EXECUTION

Spawned concurrent Bash workers against the same file to trigger the race on demand, then wrapped the critical section in flock -x. Varied priorities with nice/renice and observed context switches with vmstat and top -H.

SECURITY IMPACT

Shows how an integrity flaw appears under concurrency and how kernel-level exclusive locking restores correct, deterministic results.
